## Where things stand

Current release: **v0.9.32** (2026-07-28, build 25, notarized). Four fixes have landed on `main`
since that tag and are not yet in a released build:

- Story Studio: a new project could render raw noise with no explanation (`defaultConfigJSON`
  pointed at an empty model). Fixed — the controller now refuses a render with no effective
  model and shows why; the default config is Draw Things' Krea 2 Turbo.
- DT Project Browser: Send to Generate / img2img actions used the clip's cover-frame thumbnail
  or a half-size preview instead of the frame being viewed. Fixed — both now resolve through the
  full-size fetch.
- Drawer section headers only toggled from the chevron, not the row. Fixed.
- **Found, not fixed, roadmapped**: Generate only restores 10 of an imported image's 58 config
  fields (LoRAs, hires fix, tiling, refiner, negative prompt, SDXL conditioning all get parsed
  and discarded). Plan is to build a raw-JSON metadata viewer first — the diagnostic that would
  have caught this — then widen the applier.

Repo: `main` at `0187aae`, everything pushed, test suite 168, zero failures.

## Remaining issues, in README priority order

1. **Export All should offer `.mp4`** — it currently pages over raw database rows rather than
   the grouped slots the grid shows, so a 5-clip project writes ~1,285 loose frames. Decide the
   audio question first: `VideoAssembler` is video-only today, so `.mp4` export would be silent
   even though clips carry real soundtracks the browser already plays.
2. **Video handling — general pass** — playback, audio, and frame-accurate Send to Generate /
   Export This Frame have all shipped. Still open: a wider look at how series are handled outside
   the DT Project Browser, and whether "expandable in place" (spec §7) is still wanted now that
   clip playback and the detail scrubber exist.
3. **Story Studio configs — make the base config easy to change** — it's currently a Swift
   string literal requiring a rebuild to tune. Four-step plan already scoped: "Use a saved
   config…" picker in Project Info → make the new-project default a setting → reuse the same
   mechanism everywhere a config already exists → "send render to new Story Studio project."
   **Decided:** snapshot, not live reference — a live link would retroactively change what
   existing projects render, which collides with the reproducibility work already shipped.
4. **Generate drops most of an imported image's settings** — see above. Build the raw-JSON
   viewer first.
5. **Render queue — matrix in, job list out** — replaces the dead "Workflow Builder" Labs stub.
   Design is fully settled: define axes → Expand → flat queue of full standalone-config jobs →
   prune/reorder/pause/run. One engine pass per job (failure isolation). Compiles to StoryFlow,
   following the Story Studio precedent — not built inside the StoryFlow editor or inside
   Generate. Just needs building.
6. **README polish** — screenshots, demo GIF.
